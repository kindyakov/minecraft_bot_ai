# Domain docs

Раскладка проекта — single-context. Все пути ниже заданы от корня
репозитория.

## Перед исследованием кода

1. Прочитай `CONTEXT.md`, если он существует.
2. Прочитай относящиеся к задаче ADR из `.agents/adr/`.
3. Используй определения терминов и учитывай принятые решения
   при анализе реализации.

Если этих файлов нет, продолжай без предупреждения и без предложения
создать пустые документы. Их отсутствие не блокирует работу.

## Владельцы содержания

- `CONTEXT.md` — словарь доменных терминов, без деталей реализации,
  планов работ и спецификаций.
- `.agents/adr/NNNN-slug.md` — решения, их причины и существенные
  компромиссы.
- `ARCHITECTURE.md` — карта кода, границы модулей и правила расширения.
- `AGENTS.md` — порядок работы и ограничения агента.

Используй термины словаря в задачах, тестах и предложениях.
Если определения нужного понятия нет, проверь существующую лексику;
при реальном пробеле уточни термин через domain-modeling.

## Создание и изменение

Для изменения словаря или записи решения используй domain-modeling.
Пути из этой конфигурации заменяют стандартные пути навыка,
включая пути в его шаблонах.

Создавай `CONTEXT.md` при появлении первого согласованного термина,
а `.agents/adr/` — при записи первого существенного решения.
Номер ADR — следующий после максимального существующего номера
в `.agents/adr/`, начиная с 0001.

Не дублируй архитектурные правила в словаре или конфигурации.
ADR хранит причину решения; текущие правила остаются
в соответствующем файле-владельце.

Если предложение противоречит ADR или ARCHITECTURE.md, явно укажи
расхождение и согласуй изменение контракта перед реализацией.
